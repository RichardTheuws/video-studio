# Lessons — video-studio

Generic, reusable lessons condensed from real production work: trailers, brand leaders, explainers, product films, UI walkthroughs. Each entry is the lesson plus why it matters; measured numbers are kept because they are the evidence. Grouped by topic. When you learn a new one, append it under the right heading.

## Build & tooling gaps (macOS / brew)

- **A brew media-tool install can break another's dylibs.** `brew install imagemagick` bumped x265; ffmpeg then looked for a `libx265.<v>.dylib` that was gone and `ffprobe` failed. Fix: `brew reinstall ffmpeg`. *Why*: check after every brew install of a media tool that ffmpeg/ffprobe still run, and restore immediately — tools silently clobber each other's shared libraries.
- **Homebrew ffmpeg has no `drawtext` and no `subtitles`/`ass`.** The bottle is built without libfreetype and libass (verified on ffmpeg 8.1.2): `-vf drawtext=...` fails with "No such filter: 'drawtext'". Check with `ffmpeg -filters | grep -E 'drawtext|subtitles|ass'`. Consequence: **all** text — titles, lower-thirds, captions, even karaoke subtitles — is rendered to transparent PNG (or an alpha video) and composited with `overlay`. Karaoke = one PNG per word-state (a colored `<span>` per state) timed on the beats; don't count on an ASS file with `\k` tags. Contact sheets can't be labeled with drawtext either: use `tile=` and compute timecodes from the `fps=` value, or label afterwards with `magick`. *Why*: this is also the higher-quality route (real typography and kerning, no drawtext escaping hell). See **Titles & text rendering** below for the toolchain.
- **The regular brew-ffmpeg lacks `zscale`/zimg/libplacebo.** The `tonemap` filter needs zscale to linearize, and the `colorspace` filter does not support `itrc=smpte2084`. Fix on macOS: `brew install ffmpeg-full` (keg-only, doesn't clash) → binary at `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`, which has zscale. *Why*: use that binary for footage builds with HDR sources; add `ffmpeg -filters | grep zscale` to preflight for footage mode.
- **`crop=...:eval=frame` does not work in every ffmpeg build** ("Option 'eval' to filter 'crop': not found"). For a per-frame animating reveal/crop, use an **overlay with an animated y/x expression** (`overlay=y='36*pow(1-clip((t-T)/D,0,1),2)'`) or an alpha `fade` — both widely supported. *Why*: don't assume a filter option exists; feature-probe.
- **Homebrew ImageMagick has no working pango delegate.** `magick -list format` shows `PANGO* PANGO ---` — the `---` means "known format, not readable". `magick pango:'...'` therefore always fails with "no decode delegate", whatever the quoting, and a `brew reinstall` won't fix it (homebrew-core builds IM without pango). Never silently degrade to `label:`/`caption:` (freetype) — that loses variable-font axes, real letter-spacing and rich markup. Use `pango-view` instead (see **Titles & text rendering**). Also: `-linecap` is not a top-level option (use `-strokelinecap` or omit).
- **ImageMagick may have no default font at all.** `magick montage` fails with "unable to read font" / a `RenderFreetype` error even without labels, and `-font Helvetica` by name can fail too. Pass `-font <path-to-ttf>` explicitly (name lookup is unreliable; a file path always works), or build QA grids without `montage`: `magick <files> -resize WxH! +append` per row, then `-append` the rows. *Why*: frame strips are mandatory pre-delivery QA — a font error is not an excuse to skip them.
- **`yt-dlp` is not installed by default** and you need it to take apart a reference video (`brew install yt-dlp`). zsh expands patterns like `mpdecimate=hi=64*12:...` and `trans/precise*` → quote them.

## Shell pitfalls (zsh, bash, macOS)

- **The default macOS shell is zsh, which does NOT word-split unquoted `$var`, and zsh arrays are 1-indexed.** `set -- $line` or a `while IFS='|' read` loop behaves differently than in bash → fields shift or empty out and segments fail silently (in one case two API jobs went out with an empty `image_url`; a failed submit is not billed, but it's wasted time). `${ARR[$i]}` with `i=0` is empty. Fix: `set -- ${=line}` (zsh split flag), `read -rA arr`, explicit variables, start arrays at 1, or run the script explicitly under `bash -c`. *Why*: EDL/batch loops break invisibly otherwise.
- **zsh reads `$VAR[label]` as an array subscript** ("No such filter ''"). Write `${VAR}[label]` in filtergraph strings.
- **`fc-list | grep -q` fails under `set -o pipefail`.** `grep -q` closes the pipe early → `fc-list` gets SIGPIPE (exit 141) → the pipeline is non-zero → `if fc-list | grep -q …` falsely reports "not found". Capture first (`FCL="$(fc-list)"`) and match without a pipe (`[[ "$FCL" == *Fraunces* ]]`, optionally `shopt -s nocasematch`). Same applies to any `producer | grep -q` check.
- **`read a b < <(identify ...)` kills a `set -e` script.** `identify` doesn't end its output with a newline, so `read` returns 1 even though the values were set. Use `WH=$(identify -format '%w %h' f); W=${WH% *}`.
- **In bash, `local a="$1" b="$V/$a"` expands `$a` before it is assigned** (with `set -u` the script dies). Split `local` declarations onto separate lines.
- **macOS APFS is case-insensitive: `t3.png` and `T3.png` are the same file.** An intermediate `t4.png` next to a card `T4.png` made the composite overwrite/delete itself with `rc=0`. Give intermediates their own prefix (`_txt_T4.png`) and verify with `ls -la`, not with "no error".
- **A helper that always writes to one fixed tmp file corrupts multi-layer composites.** A `render_text(...) -> "/tmp/_pg.png"` helper used for several layers in one `magick` command makes every layer point to the same path → N copies of the last text, titles vanish. Use a unique tmp name per call (a counter).
- **`bash build.sh | tail -1` hides a failing build.** The pipe returns `tail`'s exit 0; a stage that died on a quoting error left the old intermediate in place, and three "fix rounds" re-assembled the same stale file into a new export. Log every build step separately with `rc=$?`, compare the **mtime of intermediates** against the export, and take QA frames from the file you actually deliver, at the timecode the viewer mentioned.
- **Never pass large data URIs on the command line.** A base64 keyframe in `jq --arg` or a curl argument hits macOS ARG_MAX (~1 MB; two 2K JPEGs is enough) → "Argument list too long", or worse: the request goes out with no body and the API answers `{"detail":[{"type":"missing","loc":["body"]}]}` while your script reports the job as submitted. Build the JSON body in a file (python, or `jq --rawfile`) and send `curl --data-binary @body.json`. Downscale keyframes first (1280×720, q88 is plenty when the model outputs 1080p from 720p input anyway).

## ffmpeg filtergraph

- **Commas inside ffmpeg expressions** (`min(a,b)`, `if(...)`, `clip(a,b,c)`) break the filtergraph parser. Escape as `\,`, avoid them, or put the whole graph in a file and run with **`-filter_complex_script`** (commas inside quotes then stay intact).
- **A `#` comment inside a `filter_complex` string silently breaks the graph.** No error, exit 0 — but a wrong result (a title overlay landed hundreds of pixels below the frame because the rest of the graph parsed differently). Put explanations above the command, never between filters. Also: `gblur` takes no per-frame expression for `sigma` — it's a static option.
- **`ffmpeg concat` lists should use absolute paths** — relative paths resolve against the list file's location, not the cwd.
- **Mux audio and video decoupled.** A combined `filter_complex` with video grade + `amix` mysteriously swallows SFX. Render video separately, audio separately, then `-c:a copy`. Use `amix=normalize=0`; no `weights=` with spaces.
- **`xfade` requires matching timebase AND frame rate.** Typical errors: `timebase 1/12288 do not match 1/12800`, `First input link main timebase (1/24) do not match ... (1/12288)` (a leader/outro whose video inherited a timebase derived from 96 kHz audio), or `frame rate 24 do not match 25` (zoompan/loop defaults are 25fps). The graph then fails with `-22 Invalid argument` and writes nothing. Pin every input before xfade: `fps=24,setsar=1,settb=1/24,setpts=PTS-STARTPTS` — settb alone isn't enough. *Why*: this hits every time sources come from different pipelines.
- **Concat-demuxer with `-c copy` over separately encoded segments, then `xfade` = a truncated film.** PTS jumps from the copy-concat stopped an xfade chain at 26s where 58s was expected, with no error. Always re-encode concatenated segments (same `-r`, same `-pix_fmt`) before feeding them into an xfade chain.
- **`zoompan` on a looping still inflates duration.** With `-loop 1 -t 3 -i still.png`, `d` counts frames *per input frame*, and the looping input delivers 75 of them (3s × 25fps) → `d=72` gives 5400 frames = 207s instead of 3s. Don't use zoompan for a hold (and see the Ken Burns rule below); if you genuinely need a scale animation, feed a single frame (`-frames:v 1` / `loop=1:size=1`) or use `scale` with an expression.
- **`blend=all_mode=screen` directly on yuv420p gives a magenta cast.** The blend works per plane, so the chroma planes get "screened" too. Convert both streams to `format=gbrp` first, blend (`blend=all_mode=screen:shortest=1`), then back to `format=yuv420p`. Same for other blend modes. FX overlays generated on pure black then composite cleanly (black→transparent); `lumakey` is the alternative.
- **An image-sequence input can break the `enable` timing of other overlays.** The same `overlay=...:enable='gte(t,X)'` rendered correctly without the sequence input in the graph and not with it, while the sequence itself landed fine. Don't fight it: bake the second layer into the sequence (one stream instead of two). Also mind input indexes: `-framerate N -i seq_%03d.png` counts as one input, so everything after it shifts — a swapped index puts a full-frame sequence where a small caption should be.
- **`tile=` with more frames than tiles wants a second output file** → add `-frames:v 1`.
- **Synth SFX beat AI SFX for sharp hits** (AI produces broad "whoosh" blobs). Build impacts from `sine` + `anoisesrc` + `lowpass` + `aecho` with attack at t=0, and place them on the visual hit via `adelay`.

## Still-image inputs & runaway durations (the recurring silent failures)

- **A `-i image.png` input without `-loop 1` is a single-frame stream at t=0.** Any time-based `fade=alpha=1` (or other temporal animation) then evaluates only at t=0, so the layer stays permanently at its t=0 value (typically fully transparent) and **vanishes silently** from the render — the rest of the render "works" perfectly. Fix: `-loop 1 -t <end+0.5> -i image.png`; fades on absolute times; overlay with an enable window, e.g. `[1:v]format=yuva444p,fade=t=in:...:alpha=1[t];[0:v][t]overlay=0:0:shortest=1`. *Why*: this silently costs a full render; a frame-strip inspection catches it. Position expressions (`y=f(t)`) *do* work on a still (overlay evaluates per main frame); only filter animations on the still input do not.
- **Always set `-framerate` before every `-loop 1` image input.** Without it the input defaults to 25fps; a `zoompan` with `fps=30` counts output frames per input frame (d=1), so the clip ends up shorter than intended (3.07s instead of 6s). In an xfade chain that shifts everything after it forward, and the video stream ends before the audio/container duration — symptom: `ffprobe format=duration` looks right, but `-ss` past the real video end gives "Output file is empty". When debugging a chain, check `-select_streams v -show_entries stream=duration` per building block.
- **Every `-loop 1` overlay must be end-bounded.** A looping watermark PNG with no bound turned a short 9:16 preview into a 48-minute encode. Use `overlay=...:shortest=1`, an output `-t <dur>`, or drop `-loop` when no temporal animation is needed.
- **Playwright `recordVideo` webm + `overlay=shortest=0` = segments 33× too long.** The webm timestamps get mis-scaled by ffmpeg, and with `shortest=0` the output takes the duration of the longest input (the runaway webm, not the `color` background): 218s instead of 6.5s, consistently ×33.4. It nearly passed QA because the xfade chain cuts at fixed offsets so the total film duration was right — the only symptom was ~0.3–0.5s of grain on each transition where the chain blended in frames from a runaway segment. Three locks, because one isn't enough: `-fflags +genpts` on the webm input, `shortest=1` on every overlay, and `-t "$dur"` on the output too. Add a guard that compares each rendered segment's duration with the requested one and stops hard on mismatch.
- **Self-QA every deliverable on duration and resolution** with `ffprobe` before handing it over. A runaway duration is by definition a broken encode, and a correct total duration proves nothing about what happens inside the transitions — measure segment durations, not only the final film.

## Color / HDR

- **HDR source leaks HDR tags → wrong colors in SDR players.** 4K phone footage is often HDR (`pix_fmt=yuv420p10le`, `color_space=bt2020nc`, `color_transfer=smpte2084` (PQ)). ffmpeg drags those tags into the output without converting → the output is mis-tagged as HDR while the pixels are SDR range → players show everything oversaturated (classic symptom: a muted brand blue goes electric/royal). *Why*: the hex can be exactly right and still look wrong.
  - **Detect (mandatory in source hygiene)**: `ffprobe -select_streams v:0 -show_entries stream=color_space,color_transfer,color_primaries,pix_fmt`. `bt2020` / `smpte2084` / `arib-std-b67` (HLG) / `*10le` = HDR. Treat `is_hdr` as `color_transfer ∈ {smpte2084, arib-std-b67}` and tonemap only HDR sources (running an SDR source through the tonemap chain washes it out).
  - **Fix**: tonemap HDR→SDR bt709 and tag the output explicitly: `zscale=t=linear:npl=100,tonemap=hable,zscale=t=bt709:m=bt709:p=bt709:r=tv,format=yuv420p`, encode with `-colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv`.
  - **CLI flags alone don't force the tags**: libx264 output often keeps `smpte2084`/`bt2020`, and `xfade` silently upcasts to `yuv444p`. Set frame metadata with the **`setparams` filter** at the end of each graph (`setparams=colorspace=bt709:color_primaries=bt709:color_trc=bt709:range=tv`) + `format=yuv420p` after every `xfade`. **Always verify the output tags** (`ffprobe`) — all three (space/transfer/primaries) must read bt709.
- **Don't run the film grade over a light typographic end-card.** One uniform grade + vignette + grain over the whole xfade chain turns a white end-card grey (vignette corners, grain on flat white). Grade the chain up to the last footage clip, then xfade the end-card in afterwards — the card stays brand-clean, the footage keeps the film look.

## Source orientation & aspect

- **Check source orientation before choosing an aspect.** Phone video is often shot vertical but stored as a landscape stream + rotation tag (`stream=1920x1080` + `rotation=-90` → displays as 1080x1920). `scale=1920:1080` on such material stretches it flat (people go wide). Check first: `ffprobe -select_streams v:0 -show_entries stream_side_data=rotation` (and decode one frame for the real display dims). *Why*: if 9:16 looks native-perfect but 16:9 looks stretched, your source is vertical — vertical is then the master and landscape is a compromised derivative (see `landscape-from-vertical.md`).
- **Resized inspection strips hide aspect and framing errors.** A strip that scales every frame to a fixed geometry looked fine while the 9:16 had an empty letterboxed leader and a clashing hero — only visible on native full-res frames. Inspect at least one frame per segment at **native resolution**, and check `sample_aspect_ratio`/`display_aspect_ratio` with ffprobe (SAR ≠ 1:1 = stretched).
- **A vertical leader from a 16:9 style frame needs real vertical design.** Centering the 16:9 frame on a same-colored canvas gives a small band in empty space (worst light-on-light). Fill the vertical space deliberately (wordmark above, tagline/handle below) or design a real 9:16 card.
- **9:16 keyframes from 16:9 (or vice versa) must be their own generation.** Cropping a 16:9 composition to 9:16 cuts it apart. Going the other way, when widening 9:16 keyframes to 16:9: **don't pass the location anchor as a second reference.** With (own 9:16 frame + location anchor) and a generic "widen to 16:9" prompt, 5 of 8 frames came back as the anchor's establishing wide — the specific framing (drawer, map, top-down, binder) disappeared. What works: only the shot's own 9:16 frame as reference + the original shot prompt (size, height, action) + "match framing distance and camera angle; only widen to 16:9". ~$0.20 per frame extra.
- **9:16 from a 3D rig: FOV and camera end points must change, not only the viewport.** A portrait viewport (1080×1920) with the same perspective camera sees far less horizontally. (1) Raise the FOV (55 → 78 in one case; equal horizontal coverage would need ~117° and distorts, so pick a middle value). (2) Pull interior-dive end points back along the view direction — compute it as −(look − pos), not by hand — otherwise the camera ends stuck on one object instead of showing the room.

## Image generation & consistency

- **Hold subject/style constant across shots via an anchor reference.** Generating each image with the first strong image as an `-r` anchor kept nine characters + one style consistent across six pages. Generate text-free and add lettering separately; keep the text-free masters for re-lettering. *Why*: image-gen renders text unreliably, and without an anchor the model drifts.
- **Negative prompts don't remove brand logos.** nano-banana kept putting a real outdoor brand's logo on jackets despite an explicit ban. Solve it optically: extreme shallow depth of field turns any logo to mush. (See **Prompting the video model** — the same holds for negative prompts in general.)
- **nano-banana bakes in 2.39:1 letterbox bars** unless you demand "full frame edge to edge, no black bars, no letterbox".
- **Ask for a "black" garment? Measure that it IS black.** "Deep black cotton" came back mid-grey. A print taken from a black shirt can never look right on a grey one.
- **Name product scale explicitly in a generated frame.** A 120 cm two-seater ottoman became a "small block" once a person was added. Give dimensions and a human yardstick in the prompt ("two adults sit side by side") and pass the photo of the large variant as the first `-r`.
- **Keying eats your character when their clothing is near the key color.** `nano-banana -t` generates on green and keys with colorkey+despill; a character in an anthracite-grey coat came out half transparent (torso alpha averaging 50–55%, spots at 11%) — it doesn't read as a render bug, it looks like an opacity setting, and every derived composite inherits it. Pick a key color absent from the character's palette (magenta `#FF00FF` for a white/anthracite/yellow/black/skin palette), generate on it, key yourself, and despill magenta with `-channel RB -fx "u - 0.75*max(0,((u.r+u.b)/2)-u.g)"` (spares yellow and skin; without despill the coat turns purple).
- **Measure the alpha of every cutout before it goes into a montage.** `magick cutout.png -alpha extract -crop 200x200+X+Y +repage -format "torso-alpha %[fx:mean*100]%%\n" info:` — below ~98% on a torso area = broken. 50% alpha is nearly invisible on a dark background and obvious on a light scene, by which point it's in twenty shots.
- **A walk cycle as a sprite sheet in one generation** (6 poses side by side, "same size, same eye level") animates a character without i2v — which breaks character DNA. One generation gives identical lighting, and registration is surprisingly good (top within 1px, height within 0.8% — that difference *is* the walking bob). Two traps: (1) poses touch the slice edge → a neighbor's arm leaks into the slice; keep only the largest connected shape per frame: `-alpha extract -threshold 50% -define connected-components:area-threshold=150000 -define connected-components:mean-color=true -connected-components 8`. (2) Don't `-trim` after slicing — each frame gets its own canvas and the character jitters; keep the shared slice canvas. Play back with `-stream_loop N -framerate 12 -i frames/w%d.png -c:v qtrle -pix_fmt argb` → an alpha `.mov` you can overlay. 12 fps reads as deliberate stop-motion; 24 fps needs 12 poses.
- **Virtual try-on models collapse on cinematic frames.** Tested FASHN v1.6 on a dark concert photo: it replaced a man's head with a garment. These models are trained on e-commerce imagery; test per case with one call (~5s). See `print-on-product.md`.

## Image-to-video models (Kling / Veo)

- **The keyframe carries the motion — not the video prompt.** Shot: "low angle on a dry ceiling, one last drop falls". Measured motion energy (see **Measuring before you claim**): v1, Veo 3 Fast, "the drop falls out of frame" → **0.08** (fully static for 4s); v2, same keyframe, much more explicit motion prompt + a camera move → **0.10**; v3, **different keyframe** — extreme close-up into an overflowing bucket with the crown splash and rings already in frame → **8.36**. Two prompt rewrites gained 0.02; one keyframe swap gained ×100. The model continues what's there; it can't invent motion in a plane with nothing to grab. *Rule*: if a shot doesn't animate, replace the keyframe with one where the motion is already frozen in (splash, spray, something mid-air, motion blur), or replace the shot with one that carries the same beat with a moving subject. Stop after one failed prompt attempt; the second is wasted money.
- **i2v holds or degrades the keyframe — never improves it.** Fix skin texture, sharpness and style upstream in the keyframe, or downstream with grade + grain in the edit.
- **Generate long, cut short.** i2v models start at your keyframe and need time to get going. Measured on one teaser: the strongest 2.5s window of the opening shot started at **3.42s** — the first 3.4s of the film were dead run-up; on two other 8s clips the best windows sat at 5.46s and 3.46s. Using every clip at the length the model happens to return (4/6/8s enum) produced 57s in exactly one tempo and read as a slideshow. Generation length and cut length are two different numbers; the second belongs in your shot list. Measure the window (motion energy per frame), don't guess.
- **Late action needs a dense strip at the end.** On a 6-frame strip Kling v3 seemed never to make a jump; three draws on 8 frames showed it always comes — in the **last ~0.7s**. Judge "action missing" only on a strip that densely samples the last quarter.
- **Lock the camera with a prompt prefix, not a negative prompt.** *"Locked-off static tripod camera, no camera movement of any kind, no zoom, no pan, no push-in, the frame stays completely fixed. Only [element] moves…"* — 12/12 garden photos came back camera-locked.
- **Never i2v a letterbox strip, collage or UI screen.** The model treats black/brand bands as something to push through → the image expands/zooms and hallucinates content outside the original crop (a portrait appeared on a meeting-room wall). UI screens, text strips and letterbox collages = static hold. Always compare first vs last frame before using a clip: same framing = OK; expanded = KILL.
- **Abstract "coalesce/unite" prompts drift to recognizable icons.** "The five element colours swirl together into one warm glowing form" gave a clear **heart**. Specify the geometry ("a vertical column of light", "a spherical orb, radially symmetric, NOT a heart shape") or anchor with a keyframe that already shows it.
- **Stylized 3D cartoon characters get reinterpreted.** On-model keyframe (dust coat, white helmet, hi-vis collar, tape measure); two Veo 3 Fast runs both drifted: coat → blazer, collar → dress shirt, props gone, beard shorter, plus camera drift — despite negative prompts and a prompt asking literally for a locked-off shot. One run had wide-open eyes and an open mouth (unusable). Text baked into a sign survived fine. When character DNA is fixed and the motion only needs to add "life", i2v is the wrong tool: use a subtle push-in on the approved keyframe instead (`zoompan` on a 1.5× upscaled source, z 1.0 → ~1.055 over the duration, + `noise=alls=4:allf=t+u` against banding). Character is 100% consistent and text stays still. This is the one sanctioned exception to the no-Ken-Burns rule; see below.
- **Hanging fabric comes loose when you pull out.** A pull-out away from a large stretched banner/backdrop makes Veo reconsider the hanging point: the cloth sags, folds and shrivels, and the print becomes unreadable. A push-in holds. Always drive toward hero text on textile, and say so: *"the banner stays taut, fixed and firmly hung, it does not move, sag, fold or come loose"*. Want scale? Put it in the keyframe (wide frame) rather than revealing it with a pull-out.
- **Pre-composited print survives i2v.** Keyframes with print composited in beforehand survived all 14 i2v clips intact (prompt line: *"the printed lettering must stay exactly as it is: unchanged, correctly spelled and legible"*). But a carrier framed too small doesn't become legible through a push-in — frame it large enough from the start (85mm instead of 50mm).
- **Only start+end-frame models drive a real continuous transition.** Kling has `tail_image_url` (v2.5) / `end_image_url` (v3); Veo has no end frame. An `xfade` between separate shots is a dissolve, not a transition.
- **Kling start+end frame with small angle steps spins a near-full orbit in 5s** and lets small logos float. On a product detail tour, at 2.6s a different glyph appeared on the side than the real small logo. Put labels/reading moments on the keyframes; keep the transition ≤1.2s or speed it up. If you use a Kling orbit between two poses, take the **last window** (~1.4s arriving at the end pose) rather than the whole clip sped up — a 0.28× PTS whip shows the front twice. A flip from top to inside of a cap does work in one move.
- **Don't build a product turntable from Kling orbits at all.** Even the "clean" last window still carried a second cap visor (visible frame-by-frame at full res, not on a 6 fps strip). An ambiguous object makes every orbit hallucinate somewhere. With ≥6 real product angles (product photography nearly always has them): poses 1.2–1.5s each with a 4% push, 0.25s dissolves, labels on the pose — an honest product carousel, pixel-exact. Keep Kling for the **journey** (product → in use), where a hallucination in transit is masked anyway.
- **Content checking applies to the prompt text, not only the image.** Veo returned `422 content_policy_violation` on "small child silhouette ... small in the corner"; "small **child-height shadow** in the foreground" (same image) passed. Avoid the bare noun "child" next to "small/corner". A blocked prompt generates nothing and isn't billed.
- **Veo 3 Fast i2v specifics** (`fal-ai/veo3/fast/image-to-video`): `generate_audio:false` works reliably, ~48–75s per clip, 720p, $0.10/s. Params: `duration` enum `4s/6s/8s` (with the `s`), `aspect_ratio` `auto|16:9|9:16`, `resolution`, `negative_prompt`, `safety_tolerance`. A 2.39:1 keyframe with `aspect_ratio:auto` comes back **16:9** (1280×720) — letterbox in the edit if you want scope. `seed` is accepted but **not honored**: two renders with identical prompt and seed differed as much as two with different seeds (22.78 vs 24.02 on a coarse grey grid) — don't count on reproducibility, design A/B tests unpaired. Image URLs must be publicly reachable. Calm Veo motion: longer clips (8s) + "minimal, very slow, subtle, smooth, camera locked, background perfectly still"; short clips with big gestures look jerky.
- **fal retires Veo 3 / 3.1 Fast i2v (`veo3/fast` and `veo3.1/fast/image-to-video`) on 2026-10-25; Kling v3 Pro replaces it as primary — measured, not assumed.** Anything that builds model calls from a registry needs migrating before that date. Test bench: same keyframes + prompts as an earlier Veo production (baseline), Kling v3 Pro vs Gemini Omni Flash, plus an end-frame transition and one 9:16 shot (~$7). **Gemini Omni Flash = KILL**: in 2 of 3 shots it chose a new camera position (frontal, closer) and in one the hero got a different face — that breaks keyframe-first; fast (~40s) but max 720p. **Kling v3 Pro = PASS**: holds face and framing tightest; the end-frame transition drove the requested ascent (v2.5 had him run off low); 9:16 native 1080×1920 with a fixed camera. Practicalities: v3 outputs **1928×1072**, not 1920×1080 → always scale+crop in the edit or xfade/concat with other clips breaks. Field names differ from v2.5: `start_image_url`/`end_image_url`. End-frame jobs took ~16 min (plain shots ~2 min) → run them as background tasks. A 7-shot production cost $3.58 generation per format.
- **Kling's queue can run for hours**; cancel via the API. Call models schema-aware: fetch results via the base-model path / `response_url`, poll `status_url`, retry the result fetch. Reuse a tested queue wrapper rather than rebuilding polling.

## Prompting the video model (tested, not believed)

Three rules from a commercial AI-film product were tested against our keyframe-first workflow. All three FAIL — each time because the failure mode they address doesn't occur when you do i2v from your own keyframe. The lever is upstream, in the keyframe; don't add prompt ceremony around the video model.

- **`negative_prompt` is decoration on Kling i2v** (`v2.5-turbo/pro`, measured with a positive control). Same image, tail image and prompt; only the negative prompt varied; n=4 per arm (no `seed` on that endpoint, so no paired comparison); metric = high-frequency skin texture on an NCC-tracked, normalized face crop relative to the source photo; decision rule fixed in advance (PASS only on perfect separation, U=16/16). (1) Anti-"plastic skin, waxy, CGI sheen, AI gloss" negative: U=9/16 where 8 is chance — pure noise. (2) **Positive control**: a negative banning "color, saturated colours, orange light, purple light, neon" left mean saturation at 0.4164/0.4158, inside the baseline range, with the orange-purple LED room fully intact — Kling ignores the field. (3) The same skin wish as a positive prompt line: U=3/16, no improvement. *Rule*: skin texture isn't promptable in either channel; fix it in the keyframe or with grade + grain. This generalizes the earlier anecdotes (logos on nano-banana, character drift on Veo): treat `negative_prompt` as decoration, not control. (~$5.)
- **"Style first in the prompt" does nothing for i2v.** Cel-shaded anime keyframe, Veo 3 Fast, two arms with identical words in a different order, 6 seeds each: U=13/36 (18 = chance), medians 1.041 vs 1.035 — if anything the wrong way. None of the twelve clips drifted: median **7%** of the way to photorealism, max 15%. With i2v from your own keyframe, the keyframe carries the style; the rule addresses a text-to-video problem. (Untested: text-to-video, styles other than cel animation. ~$11.)
- **Role-labeling reference images adds nothing with two references.** Ref 1 = a person in a distinctive room and outfit, ref 2 = an empty neon alley; asked for the man in the alley in a bright yellow raincoat (a color in neither reference, so clothing leakage would read as a dark torso). Identical refs and order; the only variable was the role sentences ("Image 1 is a face reference ... use the face but NOT the clothing or background"). nano-banana pro, n=8 per arm: **zero leakage in either arm**, background fidelity at chance (U=30/64). The apparent "more yellow" effect (U=44/64) was framing — the labeled arm framed the figure larger (+32% coat area) while hue was equal (43.0° vs 40.8°). Order convention (1st ref = primary) suffices. Role labeling may matter at up to nine references with machine-written prompts; untested and not needed here. (~$2.)

## Measuring before you claim

- **Motion energy per clip** — the number behind "is this shot alive":
  ```bash
  ffmpeg -v error -i clip.mp4 -vf "scale=160:90,tblend=all_mode=difference,signalstats,\
  metadata=print:key=lavfi.signalstats.YAVG:file=-" -f null - 2>/dev/null \
   | awk -F= '/YAVG/{s+=$2;n++} END{printf "%.2f\n", s/n}'
  ```
  Below ~0.5 a full-frame shot is practically a still. Run it over every cut before delivery — one dead cut in an otherwise tight edit reads as a stutter. The same per-frame series, windowed, finds the strongest N-second window to cut.
- **Screen recordings need a different motion measure.** On UI captures with a light background, a scroll or cursor changes only a few percent of mean luminance: 7 of 14 beats scored "practically still" while 41 actions happened in the lowest one. Use the **longest contiguous still interval** (YAVG < 0.15) and test it against ~3.5s. That measure exposed the real problem: every beat ended with 3.5–5.0s of standstill (the closing `sleep` in the capture script) — back to back, that's the slideshow failure. Let the edit find the last motion and end ~0.8s later (upper bound = storyboard duration, lower bound = what the adjacent card needs to be read).
- **Count real cuts in a reference with scene scores.** `select='gt(scene,0.0)',metadata=print` → sort by score. A sequence whose top score is 0.44 and the rest ≤0.22 has **one** real cut; everything else is masked — that's the key question when reverse-engineering an edit. `-v error` also suppresses the `showinfo`/`metadata=print` output you want; use `metadata=print:file=-` with `2>/dev/null` instead.
- **Measure against the source before demanding precision.** A reference "morph corridor" was assumed to need pixel-identical walls between style plates. Measured on the reference itself (edge map 256×144, DSSIM between consecutive style plateaus): **0.38–0.43**, 0.37 first-to-last. What sells it as one corridor is continuous camera motion plus a centered, equally sized doorway at the vanishing point. Generate variants with the first frame as `-r` anchor + "same camera, same doorway size and position", and test against the 0.38–0.43 band; chasing 0 costs re-rolls the source itself never achieved.
- **A positive control is not optional.** Without one, a null result reads as "the claim is false"; with one it can read as "the knob isn't connected" — a very different and more useful verdict.
- **Validate the tracker before the metric.** A first analysis gave a false negative because an NCC face tracker, at low scores, sat on a smooth brown door that slipped through a YCbCr skin mask (brown is in the skin range). Only a contact sheet showed it. Threshold NCC ≥ 0.70; below that the crop isn't the face.
- **Test your metric's sensitivity.** A known σ=0.5 blur on the same clip dropped the metric by 0.09 — as large as the whole between-arm difference. So the instrument could see the effect; it just wasn't there.
- **Calibrate a style metric on a content-matched twin.** Generate the same scene twice — target style and photoreal, same description — as your ruler for "full drift". Without it, three plausible measures were all wrong: flatness (a photoreal billboard frame scored 0.749 vs cel 0.635 — it counts skies and walls), palette compactness, local uniformity — all content-driven. What worked: **mid/edge ratio** (continuous shading gradients over hard ink lines): cel 3.13 vs photo 5.39. Watch resolution: the same measure had +72% range at 1080p and only +14% at 720p; recalibrating on the twin pair restored +58%. A measure with no range at your measurement resolution produces a meaningless null.
- **An area measure measures framing, not compliance.** "How much yellow is in frame" scales with how big the subject is. For color compliance measure the **hue** of the region, not its area. For any fraction measure, split size from property and measure both.
- **Sample a transition at several points, and read frames accurately.** Use `-i file -ss t` (accurate), never `-ss t -i file` (can return a half-decoded frame). One frame in the middle of a dip-to-black is dark and always looks fine.
- **A cheap test beats a plausible rule.** Each of the three prompt tests above cost roughly the price of a few clips — cheap insurance against a plausible but wrong rule entering the skill.

## Directing & rhythm

- **Footage first, not copy first — every line must be proven by its shot.** Two cuts were rejected because "the images don't match the message": the copy was written first and footage searched for afterwards, from too thin a pool (6 of 167 clips) → generic b-roll that didn't *prove* the lines ("your music" with no music shot; three activity claims over one festival shot). Inventory the **strongest real moments** in the whole pool first and let them shape the story and the exact words. One proof shot per line; if a claim can't be proven with an image, cut or rewrite the claim. Mine the brand's own earlier promos for how they map activities to footage and for their voice. When in doubt, show the line→clip→why mapping for approval before rendering.
- **Everything at eye level = no directing.** Eleven of twelve shots at the same camera height in the same shot-size family. Size and height are free dramatic knobs; fix them in the shot list before the first keyframe.
- **A shot with three actions delivers none.** "He lands in front of the tractor, stops it with one hand, and doesn't spill his coffee" produced a man standing next to a stationary tractor. Split it, or freeze the other actions into the keyframe.
- **Measure VO length before the shot list.** Two VO lines (11s and 5.5s) didn't fit their beats (8s and 4s) and ran over the silent journey and the end card. Generate VO right after the storyboard and set beat lengths from it — or write shorter. Keep VO calm: e.g. ElevenLabs `speed` ~0.85 plus pauses; longer and calm beats rushed.
- **Pressure-test message and CTA logic before the build.** A negatively framed opener and an unverified CTA assumption went into a cut untested. Verify concept copy and CTA claims against reality before montage.
- **A teaching film without voice needs holds ≥4s per card.** A 4.0s kinetic closing card with xfades in and out is effectively 2.6s — count the fades.
- **AI disclosure must appear before the reveal peak.** In a spark-wipe from a 3D anchor to a photoreal AI render, the render is recognizable at ~30% of the wipe. A chip fading in at 1.9s for a 0.35–1.60s wipe left ~0.5s of unlabeled AI imagery — only visible on a dense strip. Put the chip at ~0.45s (fully visible at 0.75s ≈ 30% wipe) and the explanatory lower-third after the reveal.
- **3D explode moves: lifted layers must clear the end camera.** Lifting floors only a little leaves them hanging between camera and floor plan. Lift beyond the camera's end height (3400/4300/5200 cm with a camera at 2000) with a separate lift easing (`t^2.1`): slow apart so the explode reads, then accelerating out of frame.
- **Plan holds in CG should not be a linear micro-drift.** It reads as a still on the strip, especially next to a lead-in ending on the same position (10–12s of near-identical image). Use a slow orbit arc with push-in (r 760→590, height 2060→1880, ~25° sweep).
- **Don't "speed up" a CG frame sequence by reading it faster.** `-framerate 63 -i f%04d.png ... fps=30` drops frames (every second at 2.1×) → visible judder, worse on CG without motion blur. Re-render at the shorter duration (`n = dur*FPS`, same easing). `minterpolate` costs more and artifacts on hard edges. Verify with `ffprobe -count_frames` = number of rendered PNGs.
- **Don't put `fade=t=in` at the start of a clip shown as a video embed** — frame 0 goes black, and that's the thumbnail.
- **Canon vs. creative: make a hero tier, don't hide it.** A brand canon may deliberately forbid glitch/zoom-blur/trendy transitions. If the client still wants spectacle, treat it as a documented hero/brand-film tier above the social-ad canon: edge from rhythm, grade, light and speed ramps, not cheap transitions. Surface the tension; don't choose silently.

## Transitions

- **Uniform dissolves are as bad as uniform hard cuts.** The same 0.3s `xfade` everywhere is mud; between two dark handheld shots it becomes soup. Choose the transition per boundary based on the (viewed) motion; dissolve only between compatible shots.
- **Never cross-dissolve a card into a screen recording — use dip-to-black or a cut.** ~0.45s of grain over the whole app window on every chapter transition; five explanations fell in turn (segment length, generation loss over 32 re-encodes, color metadata, bit depth, frame-reading method). Cause: in a dissolve a light, finely drawn UI screen sits at ~50% opacity over a dark card, so the webm compression artifacts are relatively twice as strong as the image around them. Shorter mixing (0.25s) doesn't help — the blend itself is the problem. `xfade=fadeblack` and a hard cut are both measured clean. Keep cross-dissolves for transitions between similar shots.
- **Title plates in a dissolve double up** — two plates 0.4s over each other read as clutter. Fade the plate out before the transition, or make it a cut. A cumulative list over cuts: no fades between steps (it flickers).

## Titles & text rendering

- **Titles, cards and kinetic type: an HTML/GSAP renderer (HyperFrames) is the title layer, pango is the fallback.** HyperFrames renders HTML compositions to an alpha video (ProRes 4444) you overlay in ffmpeg; see `titles-hyperframes.md`. Lessons from adopting it:
  - **Render with `--no-browser-gpu`.** With GPU, 948/980 frames were bit-identical across two machines; the rest differed by up to 4/255 on edge pixels (anti-aliasing during scale/motion). Software: 980/980 identical, same speed. If you render on a second machine/server, its output must match.
  - **It needs Node ≥ 22.** An older `node` earlier in `PATH` makes it fail; check the version in preflight.
  - **GSAP overwrites `transform`** → don't center with `translate`; use `inset` + `margin: auto` + `height: fit-content`.
  - **GSAP doesn't interpolate `var(--x)`** → read the CSS variable first (`getComputedStyle(root).getPropertyValue(...)`).
  - **One entry file per project** → thin `916/` and `169/` folders symlinking to `shared/`; copy with `cp -RL`.
  - **Viewing a frame from a ProRes 4444 MOV**: overlaying on a `color` source gave empty frames with `-ss`; reliable is `ffmpeg -ss T -i x.mov -frames:v 1 -pix_fmt rgba o.png` + `magick o.png -background … -flatten`.
  - **`snapshot --describe` sends frames to an external model and telemetry is on by default** → set `HYPERFRAMES_NO_TELEMETRY=1` and `--describe false` in your render script.
- **Pango fallback: render text with `pango-view`, composite with ImageMagick.** `brew install pango`, then `pango-view -q --no-display --background=transparent --markup -o out.png -t "<span ...>"` → transparent PNG → composite onto plates/frames. More robust than an ImageMagick source rebuild (which breaks on `brew upgrade`). **`pango-view --width` is in points, not pixels**: at `--dpi=96`, 820 "px" becomes 1093 px and text runs out of a panel — convert with `width_pt = px * 72 / dpi`.
- **Fonts are per project, not a skill default.** Whatever fonts happen to be installed from an earlier production are not a universal default; grabbing them because they're there is the mistake. Choose a font that fits the brand (a specimen board helps), record it in the project's brand tokens + fonts folder (OFL), and render with it. A preflight font check only means "something is renderable".
- **Never pass an empty caption string to ImageMagick** (`caption:`/`label:` → `label expected`). A bash array with an accidental empty element shifts every caption by one. Map captions explicitly per item (case/dict), not via a fragile array index. Also: `label:` must come *before* `-border`, otherwise "no images for -border".
- **`-crop` doesn't enlarge a canvas — perspective text falls outside the frame.** Warping text into a print area with `-distort Perspective … -crop WxH+0+0` leaves the mapped layer at canvas size with the target coordinates (in frame coordinates) mostly outside it; you see a fragment of the word shifted top-left. Set the viewport before the distort:
  ```bash
  magick flat.png -virtual-pixel white \
    -set option:distort:viewport 2752x1536+0+0 \
    -distort Perspective "0,0 X1,Y1  W,0 X2,Y2  W,H X3,Y3  0,H X4,Y4" +repage art.png
  ```
- **Drop your own title bar where the capture already carries the message.** A lower-third over a site hero that already shows its own tagline gave double, messy text.

## Compositing & alpha

- **Never grade an RGBA layer with operations that also hit the alpha channel.** `\( +clone -alpha extract \)` followed by `-modulate`/`-colorize` applies those operators to every image in the sequence, mask included → a semi-transparent subject (the room showed through a black T-shirt). Split into three steps — write alpha out separately, grade RGB, then `CopyOpacity` — and verify with `-alpha extract -format "min=%[fx:minima*255] max=%[fx:maxima*255]"`.
- **An opaque layer over an ink layer destroys the alpha** → the next composite step darkens the whole frame. Restore the original alpha with `CopyOpacity`, and verify with a measurement *outside* the print area.
- **Cutting out from white bleeds color, not just an alpha fringe.** Stretching alpha doesn't help; erode the mask ~2px inward, then use the standard `-shadow` idiom rather than stretching alpha levels yourself.
- **PIL `convert("RGB")` throws away your alpha.** Artwork carrying its ink mask in alpha must be loaded with `convert("RGBA")` — otherwise the output is byte-identical to the version without the mask and you think your fix did nothing.
- **Transparent overlay screenshots need a transparent page.** When rendering overlay PNGs from HTML (`omitBackground:true`), a shared base CSS that sets a `background` on `html,body` makes them fully opaque — the capture underneath disappears when the overlay fades in. Inject `html,body{background:transparent !important}` in the overlay pass. Check: `magick identify` must report `srgba` and alpha mean < 1 (`-alpha extract -format "%[fx:mean]"`).
- **A phone green-screen plate has a time window, not a fixed matte.** As the person approached, the ceiling line of the cloth dropped: until 1.9s the head was fully covered by green, from 2.2s the glasses poked into the ceiling band and any fixed garbage matte cut them off. Find that window with a keyed frame strip before choosing the matte. Measure the cloth color (`%[pixel:p{x,y}]`) — here `#2DBB51` at similarity **0.10**; at 0.14+ the key eats skin, at 0.28 the whole person disappears.
- **Particle/spark overlays: HTML canvas + a headless browser works very well.** Additive particles (shadowBlur glow, star shapes, glow-band gradient) on black, rendered per frame via a `window.renderFrame(t)` hook + screenshot, then screen-blended (in gbrp, see above) over an `xfade=wiperight` with a matching front speed.

## Mono logos & branded lockups

- **A mono (single-color) logo variant flattens a detailed emblem into a meaningless silhouette.** Use the full-color logo with a glass panel (a brand-color `rgba` ~0.62 + a thin gold hairline) on busy/dark shots. Mono is only for genuinely simple wordmarks. *Why*: a detailed round emblem (icons, ornament) becomes an unreadable disc when reduced to one color.
- **Build branded lockups as a designed PNG** (rounded panel + hairline + full-color emblem) rather than a flat ffmpeg `drawbox`.
- **A v1 leader without i2v cost**: a crafted ffmpeg animation (grade + fade + xfade dissolves) on a generated style frame gives a premium leader/outro for ~$0 generation. Save i2v for where real motion matters.

## Print on product

- **Relighting is the whole difference for a print.** Warp + multiplying a blurred grey value: SSIM 0.26 against ground truth; multiplying the artwork by the *target's* light field: 0.63; log domain + robust polynomial fit + alpha-from-deviation: 0.92. Full method and measurement setup: `print-on-product.md`.
- **Never judge a print on the last frame.** A word on a doormat looked covered by a boot; on the strip the word was fully legible for the first 1.3s and the boot was the intended occluder.

## AI music & audio honesty

- **fal.ai stable-audio gives social-safe original music** (`stable-audio-25/text-to-audio`, param `seconds_total`; queue API: submit → poll status → `.audio_file.url`) → no copyright mute on TikTok/Reels, which matters for mobile-first delivery. Generate two variants in parallel and choose by ear. Keep it instrumental (underscore/bed), never a synthetic "song" imitating real pop.
- **stable-audio-25 caps at 190s** (`seconds_total>190` → 422 with `le: 190`). For longer films: two generations (main + ending) joined with `acrossfade=d=8` where the film enters its ending — the musical change then marks the act break.
- **Music must fit the brand.** An electronic pop bed failed for a brand whose earlier films used an orchestral bed ("epic cinematic orchestral, no electric guitar"). When in doubt, reuse the already-approved bed.
- **Normalize the bed to the level the FILM must reach.** A bed at `loudnorm=I=-20` mixed unchanged produced a −20.7 LUFS film, over 4 dB below target.
- **You cannot audit audio by looking.** When you can't actually hear the result, deliver it with an explicit "not heard / replaceable" caveat and note that cuts aren't frame-accurate on the beat — never sell it as finished.

## Inspection & process (the #1 failure source)

- **A time-based medium is judged densely, not on a handful of stills.** Declaring a cut "good" from ~10 tiled thumbnails misses bad cuts and dead time. Before "done": (a) dense frame strip ≤0.7s across the whole clip; (b) per cut, view the OUT-frame of A next to the IN-frame of B — a cut exists by virtue of those two frames; (c) check each card's hold/legibility on its real duration. See `commercial-craft.md` §7. Several defects in this log (unlabeled AI frames, unreadable app screens, late action, flashes of unmasked text) were visible *only* on a dense strip, some only at 10 fps or frame-by-frame at full resolution.
- **Pick cut points on frames, not arithmetic.** Determine in/out by viewing the actual boundary frames, not `frame k ≈ k/12·duration`. Cut on a clean/stable frame, on motion or beat — never mid motion-blur or on a dark handheld frame.
- **Text-card budget ≤ ~25% of runtime.** Footage carries the story; cards punctuate. A near-static opener/CTA of several seconds reads cheap/slow.
- **Never mute a testimonial to silent lip-movement** — a talking head without their voice is uncanny. Use their audio (ducked under the music) or don't make it a long shot.
- **Do a source-hygiene pass before montage**, per source: detect watermark / burned-in subs / already-present titles / already-graded look / letterbox / HDR tags. Don't double-grade; don't blindly mix watermarked with non-watermarked material.
- **Validate ONE cut before fan-out.** Rendering multiple language versions/variants before the core cut is right is wasted work. Get one core segment/cut right and approved, then produce variants/languages.
- **A visual keyframe storyboard is the cheap gate before i2v.** The money is in image-to-video, not image generation: a board of 10 keyframes (~$0.06 each, ~$0.60 total) gates an i2v render of ~$5. Show real generated keyframes, spend i2v money only after approval. Generate the board at delivery quality, not prettier — keyframes are the peak, i2v holds or degrades — so the board is an honest floor, not a shop window. First keyframe = auto-anchor for the rest. See `storyboard-keyframes.md`.
- **Deliver social at shareable file size, not master quality.** CRF 19 at 1080×1920 gave 27 MB for an 11s teaser — unusable to send in a messenger. CRF 26 (teasers) / 25 (master) gave 2.4–2.9 MB and 17 MB with no visible loss on a phone. A social deliverable that doesn't fit through WhatsApp isn't finished.
- **If you render on a second machine/server, verify it has the same tool build** (drawtext, pango, node version, fonts) before sending it a text-dependent recipe — and verify its API credentials work before starting a long unattended run.
- **For unattended runs, the QA gate on the output is the verdict, not the exit status.** A run can report success and still produce a broken file.
- **A capability gap is never silently skipped.** If a required tool is missing, stop and ask (install / alternative route / cancel), install after approval. *Why*: a missing tool is a user decision, not something to work around silently.

## Motion & "MovieMaker" register (hard rules)

- **Never Ken Burns / zoompan on stills, UI screens or cards.** Auto pan/zoom over a flat image reads low-grade — PowerPoint, not film — and makes the frame restless and jittery. Motion comes from the source (live screen recording with scroll/click/typing, streaming terminal output, animated code graphics, i2v), crafted transitions (luxe cross-dissolves, dip-to-black), strong kinetic typography, and one rich grade + subtle film grain. Static premium stills + luxe dissolves = high-end. Static holds are the default. The only exceptions: the subtle push-in on an approved character keyframe where i2v would break character DNA (see above), and scroll-video, where the camera move *is* the content (`scroll-video.md`). For other brands treat zoompan as a last resort that needs explicit approval.
- **If a still must move, a REAL element in it must come to life** via art-directed image-to-video (Kling/Veo): a crowd subtly moving, a glass raised, flickering light, hair/smoke moving. Direct the element explicitly + lock the camera in the prompt; render multiple takes and **curate**. Never "animate this" blindly → the model spins the subject on its axis. In ffmpeg the swap is mechanical: replace the still input with the i2v clip and the `zoompan=...` with `scale=1920:1080:force_original_aspect_ratio=increase,crop=1920:1080,fps=24,settb=1/24,setpts=PTS-STARTPTS`, keeping grade, overlays and `-frames:v N`.
- **Live screen recording beats stills + Ken Burns for instructional video.** Record the real flow with real UI motion: cursor, typing, clicks, page transitions. Record calmly (long holds) and edit real-time so steps stay legible; trim the lead-in (start mid-action); speed-ramp only genuinely static stretches (e.g. form filling at `setpts=PTS/1.8` took a beat from ~9s to ~5s). Verify the flow live before recording — bugs may have been fixed since, so you film the real working flow rather than a workaround.

## Capture format & environment

- **Capture format = output format.** Don't reuse 16:9 desktop grabs for a 9:16 cutdown by pasting them as cards on a background — that isn't native capture. For 9:16, render the responsive page at mobile width so the native mobile layout appears, then crop 9:16 full-bleed. Headless recipe: `--force-device-scale-factor=2 --window-size=540,<tall>` (540 CSS-px → mobile breakpoint; ×2 DPI → 1080px bitmap) → full-page PNG → `magick -crop 1080x1920+0+<y>`. Or a phone viewport (390×844 at DSF 3) for 9:16 and 1920×1080 at DSF 2 for 16:9.
- **"Native 9:16" for a fixed-width app ≠ rendering at 1080 wide.** A prototype designed at 390px stretched to tablet width at 1080×1920 and a quarter of the screen went empty — technically native, visually wrong. Use the app's own width with a 9:16 ratio (390×693) at `deviceScaleFactor 3` → 1170×2079 → downscale to 1080×1920. The bottom falls out of frame, exactly like a real vertical recording of a phone screen.
- **A whole device in a 16:9 frame makes the screen unreadable.** A 390×844 capture fitted at 90–94% frame height gives a ~450px-wide phone on 1920 with ~16px UI text — unreadable on a phone playing the video. A screen you can't read is decoration. Scale the device beyond the frame (h ≈ 1.35× frame height in a split beat, ≈ 1.55× solo) and let it run off the bottom: you lose the bottom of the screen (rarely the message) and gain ~1.7× legibility.
- **For real page-capture footage, render locally, not via a containerized browser.** A Playwright-MCP running in Docker writes screenshots inside the container — you see them inline but can't feed them to ffmpeg/magick. Use host-side headless Chrome: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --force-device-scale-factor=1 --window-size=1920,1080 --virtual-time-budget=9000 --screenshot=out.png URL`. For sections beyond the hero, capture one tall grab (`--window-size=1920,7200`) and crop sections with `magick -crop 1920x1080+0+<y>`; measure offsets on a scaled-down preview. Or host-side Playwright; if its bundled browser build is missing, launch with `{ channel: 'chrome' }` (system Chrome).
- **Fixed cookie banners overlay a viewport-sized hero grab.** Crop the hero from the full-page render instead (the fixed banner usually sits only at the very bottom there). Always inspect for banners/overlays before montage, and hide the site's own widgets (mascots, chat bubbles) before capture: grep the repo for the widget text → root class → hide CSS via `addStyleTag`.
- **Feed scroll: cap the distance, never full page.** `smoothScroll` over a >10k px feed in ~4s = unreadable white smear and you land on random content. Cap at ~2.5 viewport heights over ~5s: legible, and you decide where it ends. A full-page still panned vertically in ffmpeg (crop y linear over t) is a smooth, deterministic alternative when video recording isn't available.
- **WebGL/3D: `recordVideo` gives black frames.** Playwright `recordVideo` delivers black frames once the WebGL canvas is occluded (compositor), and headless WebGL is blank/freezes at large sizes. What works: headed Chromium + a `page.screenshot` sequence (~220 frames per ratio) → grade + blend-motion interpolation to 30fps; record 9:16 natively at a mobile viewport. Verify in-app "tour" buttons before relying on them (they may be instruction modals), and dismiss recurring onboarding modals per frame.
- **Signature move: illustration → platform.** If a site's hero shares the illustration style of your generated landscapes, a match-dissolve from landscape to UI is near-seamless. Anchor your i2v keyframes on the existing hero asset.

## Capture rigs (Playwright)

- **DOM patches and chrome-hiding belong in an init script, not after `goto`.** Masking strings (names) or hiding the site shell via `page.evaluate` after `goto`+settle leaves the unpatched text on screen for 1.5–3s, and a 250ms interval misses the first paint (a site header flashed for 2 frames on client-side navigation). Use `context.addInitScript` with a rAF loop until `<body>`/`<head>` exist, plus a MutationObserver. Both leaks passed a first QA round and were caught only by an adversarial re-check at 10 fps.
- **In an init script, `document.head` and even `documentElement` can be null.** `(document.head || document.documentElement).appendChild(style)` threw and two takes were rejected. Always rAF-loop until the element exists.
- **Hiding an SSR error flash: hide preventively, then release on `textContent`.** Routes flashed an "ACCESS REQUIRED" message for ~0.3s on each load (SSR without a session, gone after hydration). Four failed attempts: checking `main.innerText` (the text stays hidden in the DOM; `<script>` content matches too); only h1–h3 (it was a `<p>`); visible-text-node checks via observer/rAF (lost the race with the first SSR paint); preventive `main{visibility:hidden}` released when `innerText` had content (empty while hidden → never released). Working: a style rule applied **before the first paint** + a visible-text-node check + release on **`textContent`**. Remember: rAF is too late under SSR, and `innerText` respects visibility. Debug in isolation with a 100ms DOM dump, not another blind capture.
- **Masking text before hydration breaks React** (#418/#423/#425 in every beat). Start a text mask after `load`, and absorb the consequence (real text visible in the first seconds) by starting each capture's usable range 2s later in the edit.
- **"ok" is not proof.** A beat that reported "ok" had filmed a white page (dev server 500, invalid session); four such beats went into the edit. Guard in the rig: a non-stub beat with 0 logged events → reject the take, keep the existing good recording, exit ≠ 0. But mark scroll/cursor-only beats as `silent` so the guard doesn't reject good takes, and don't reject on app page errors (hydration, a 401) — that's for QA on the frames.
- **Clear the `recordVideo.dir` before every take and pick the newest file by mtime.** A rejected take left its webm behind, and `readdirSync(dir)[0]` picked the *oldest* file → stale "page not found" recordings were promoted as "ok" while the good new take sat unused; this masked three diagnoses in a row. `rmSync(dir, {recursive:true, force:true})` per take. Symptom to spot: more than one webm in the raw folder.
- **Isolate the recording server.** Another process deploying from the same checkout (`rm -rf .next`) broke every recording halfway. Use `git worktree add --detach <scratch> HEAD`, symlink `node_modules`, copy env files, run your own dev server on its own port. Then **override every `NEXT_PUBLIC_*` URL** for the new port — they're compiled into the client bundle; one pointing at the old port made all authenticated beats "not found" while SSR and curl-with-token returned 200. Diagnosis order that worked: API with token on both ports (equal) → so it's the client → grep env for the old port.
- **`next dev` returning 500 on every route with `Cannot find module './vendor-chunks/…'` = a corrupt `.next`.** `rm -rf .next` only helps if the old server is really dead (`pkill -f next-server`, port free) and the new one starts in its own session (`start_new_session=True`; a nohup-in-subshell died with the calling shell). Run captures sequentially with one owner of the server — two concurrent capture runs were the likely cause.
- **Logged-in pages never reach `networkidle`** (polling for notifications/messages). `waitUntil:'networkidle'` times out after 60s while the page is long ready. Use `domcontentloaded` + a fixed settle (~6s).
- **Staging data carries real names.** Mask names with an init script + MutationObserver before the first paint, and visually verify the mask per beat. Mint auth tokens inside the environment that holds the signing secret, with a guard that the database really is staging, and clean up the temporary script afterwards.
- **Probe every beat before storyboard sign-off.** A probe pass with expected texts per beat found four things the storyboard claimed differently (text on another route, network-wide counters on a scoped dashboard, notification language, a real process gap).
- **Film surfaces in the role they're meant for.** A page filmed logged-out showed "Could not load ..." because that block needs a session (401). Report the error too — a visitor sees it as well.
- **Sandboxed iframes and late data.** A mail preview in a sandboxed iframe isn't in `document.body.innerText` — wait for the empty state to disappear, not for the mail text. `scrollIntoViewIfNeeded` on a table that arrives with the second data round times out: scroll to the bottom and wait for a cell that should be there.
- **Driving the cursor yourself is more reliable than a mousemove listener**: set a cursor dot via `page.evaluate` per `mouse.move` step; type with `pressSequentially({delay})`; set access cookies up front (`context.addCookies`) so no unlock flash appears on screen.

## Reuse over rebuild

- **Reuse existing fal helpers instead of rebuilding the queue.** Reproducible wrappers for i2v (keyframe→mp4) and stable-audio beds already handle correct `response_url` polling. A reuse audit pays off — don't rebuild queue polling.
- **When adding to an existing brand's video pipeline, find and reuse it first.** A second video in a brand portfolio should adopt the existing branded leader→content→outro bracket, card style, music bed and delivery conventions — not spin up a parallel scratch track. Store finished films in one fixed, consistent deliverable location with fixed naming (e.g. `<brand>/<character>/<name>-16x9.mp4` + `-9x16.mp4`), working assets in a subfolder, and follow the naming already in the target folder.
- **Client brand work: consume the brand canon, reuse the EDL.** When a project has its own brand system (style guide, tokens, an existing render pipeline with a per-project EDL), read the canon first and reuse the existing structure as baseline (e.g. hook→before→process→reveal→hero→finish), not from scratch.
- **An insight from one job should enrich the skill for every future one.** When a production teaches something transferable, write it back here.
